# Architecture

GrieveAI is an API-first Flask application. Jinja pages and external clients call the same Flask endpoints, which currently orchestrate the inference and ticket persistence workflow in `app/routes.py`. SQLAlchemy stores tickets and audit events; `DATABASE_URL` selects SQLite locally or PostgreSQL when a PostgreSQL SQLAlchemy driver is installed.

The ML modules are independent of templates: `src/inference.py` exposes `predict_grievance(text)` and loads a configured model without importing training code; `src/pipeline.py` handles privacy, language metadata and the confidence gate; `src/language_id.py` implements language/script and PII rules; `src/baseline_classifier.py` provides the local baseline; `src/model.py` provides optional MuRIL+LoRA inference; `src/priority_dedup.py` supports sentence-embedding similarity with a TF-IDF fallback and deterministic recurring groups; `src/llm_report.py` validates structured OpenRouter output and uses a deterministic fallback. Final routing stays the configured category-to-department mapping; an LLM department suggestion is stored as advisory analysis. Category, department, SLA and similarity thresholds are configurable demo values.

Pipeline order is PII redaction → language/script metadata → hierarchical prediction → confidence gate → nearest similarity and recurring group → structured summary/recommendation → configured routing → ticket and audit persistence. Low-confidence submissions stay unassigned for authorized human review. Explanations are generated on an authorized admin request and failures do not affect inference. The database keeps original predictions separately from admin corrections. Duplicate matches are never merged automatically.

This repo has no direct institutional integration. The `/api/v1` routes are the intended integration boundary.
